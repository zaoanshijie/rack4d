# rock4d

使用 GitHub Actions 基于 [rsdk](https://github.com/RadxaOS-SDK/rsdk)（RadxaOS 官方 SDK）编译 [Radxa ROCK 4D](https://docs.radxa.com/rock4/rock4d) 的 RadxaOS 镜像。

## 镜像

| 镜像 | 说明 |
| ---- | ---- |
| `radxa-rk3576_bookworm_kde` | KDE Plasma 桌面版，与官方发布的桌面镜像一致 |
| `radxa-rk3576_bookworm_cli` | CLI 精简版，无桌面环境，适合服务器用途 |

- 均基于 Debian 12（bookworm）
- 均默认安装并**真正启用** SSH（见下文）
- 标准 512 字节扇区镜像（SD / eMMC 启动），首次开机自动扩容根分区
- 使用 Radxa APT test 通道软件源构建（rk3576 内核目前仅发布于 test 通道，与 rsdk 官方 CI 构建方式一致）

## SSH 默认启用（与官方镜像的差异）

官方 RadxaOS 镜像虽然安装了 `openssh-server`，但首次开机配置（`rsetup-config-first-boot` 的 `before.txt`）会执行 `disable_service ssh`，只有在“headless”时才重新启用——而 **Rockchip 板子的 DSI 连接器在驱动中无条件上报 `connected`**（dw-mipi-dsi 的 detect 回调写死返回已连接），导致 headless 判定永不成立，**无论接不接显示器 SSH 都是被禁用的**。

本仓库构建时向 rsdk 注入 customize-hook：

- 修补镜像内 `/config/before.txt` 与 `/usr/share/doc/rsetup-config-first-boot/before.txt`，移除对 ssh 的禁用
- `systemctl --root=... enable ssh.service` 确保启用链接存在
- 构建后校验 rootfs 实际状态：`openssh-server` 已安装、`multi-user.target.wants/ssh.service` 存在、before.txt 无禁用行（非仅检查 manifest）

因此**无论是否连接显示器，SSH 均默认开启**。首次开机按 rsetup 提示完成初始配置（默认账号 `radxa` / `radxa`），随后即可：

```bash
ssh radxa@<板子IP>
```

> 注：首次开机时系统会重新生成唯一的 SSH 主机密钥（`regenerate_ssh_hostkey`，官方安全行为，保留不变）。

## 版本命名

Release 以**编译所用 rsdk 提交的前 12 位 hash** 命名（如 `4e2ece0ee9e9`），镜像文件名同理；对应完整提交记录在 Release 说明中。

## 每日同步逻辑

每日 00:00（北京时间）定时执行，检测两类目标，同一 rsdk 提交只编译一次（已有对应 Release 则跳过）：

1. **官方同步**：获取 [radxa-build/radxa-rk3576](https://github.com/radxa-build/radxa-rk3576) 最新 release → 其 `target_commitish` 指向官方仓库的一个提交 → 提交信息形如 `chore: templates generated by RadxaOS-SDK/rsdk@<sha>` → 提取其中的 rsdk 版本并**按官方当时的构建环境**编译（见下方兼容补丁）
2. **rsdk main 跟踪**：编译 [RadxaOS-SDK/rsdk](https://github.com/RadxaOS-SDK/rsdk) main 分支最新提交

若两者为同一提交则只编译一份；部分目标构建失败时，其余目标仍正常发布。Release 说明中会标注目标来源（官方对应版本 / main 跟踪）。

### 对旧版 rsdk 的兼容补丁（构建前自动应用）

旧版 rsdk（如官方 r6 记录的 2025-12 版本）在当前环境无法直接构建，构建前自动打以下补丁：

- `rsdk-setup` 中的 `read -rp "Press Enter..."`（软失败时的交互等待，CI 无 TTY 会永久挂死）→ 替换为快速失败
- `devenv.yaml` 未声明 `git-hooks` input（当前 devenv CLI 无条件评估该配置并抛 `git-hooks or pre-commit-hooks input required`；上游 rsdk main 后来自行添加了该声明）→ 按同样方式补充声明
- 旧版 devcontainer 固定的 nix 2.21 / 旧 base 镜像与**最新** devenv CLI 不兼容（如 `The option 'dotenv.resolved' ... has no value defined`）→ 按官方构建当时的日期查得 nixpkgs-unstable 修订，用 `nix profile install github:NixOS/nixpkgs/<当时修订>#devenv` 安装同时代 devenv（era-pin，复现官方当时的工具链）
- 注意 `nix profile install` 而非 `nix profile add`：旧版 nix 2.21 无 `add` 子命令

## 触发编译

- **每日定时**：北京时间 00:00 自动检测上述两类目标
- **推送**：修改 `.github/workflows/build.yml` 并推送到 `main` 时，强制重编全部目标（验证 workflow；已有 Release 会被覆盖更新）
- **手动**：Actions 页面运行 workflow；可指定 main 跟踪目标所用的 rsdk ref，勾选 `force` 可强制重编

> 注意：GitHub 会在仓库连续 60 天无任何提交时自动禁用定时任务；如发现定时任务停了，随便提交一次或手动运行即可恢复。

## 烧录

```bash
xzcat radxa-rk3576_bookworm_kde_*.output_512.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress
```

也可使用 balenaEtcher / Rufus 写入解压后的 `img` 文件。

## 故障诊断

构建失败时，workflow 会自动在 [issues](../../issues) 中记录失败日志（标题 `[diagnostics] build-failure-log`），便于排查。瞬时性失败（如上游 apt 源发布中途的 404）会自动重试一次。
